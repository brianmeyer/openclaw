# MollyGraph Architecture

## 1. Executive Summary

MollyGraph is a sophisticated local-first memory system designed to provide AI assistants with persistent, queryable context across conversations. Unlike cloud-based memory solutions that incur per-query API costs, MollyGraph operates entirely on local infrastructure using open-source models—delivering enterprise-grade entity extraction, relationship mapping, and semantic search at zero operational cost. The system combines Neo4j for graph-based relationship storage, Qdrant for vector similarity search, and SQLite for lightweight metadata persistence, orchestrated through a Python-based service layer that exposes a simple HTTP API for integration.

## 2. System Components

The server is the central orchestrator built on FastAPI, providing REST endpoints for memory operations.

**Key Responsibilities:**
- HTTP API endpoint exposure (`/add_message`, `/get_context`, `/search`, `/health`)
- Request validation and error handling
- Coordination between storage backends
- Async processing for non-blocking operations

### 2.2 Entity Extraction Engine

MollyGraph uses a local LLM (originally gpt-5-mini, now Gemma3:4b via Ollama) to identify entities and relationships from text.

**Extraction Pipeline:**
1. **Text Chunking**: Split input into processable segments
2. **Entity Recognition**: Identify people, places, organizations, concepts, events
3. **Relationship Detection**: Map connections between entities
4. **Confidence Scoring**: Filter low-confidence extractions

```python
# Entity extraction prompt template
EXTRACTION_PROMPT = """
Analyze the following text and extract:
1. Entities (people, places, organizations, concepts, events)
2. Relationships between entities
3. Temporal information (dates, times, sequences)

Return as structured JSON:
{
  "entities": [
    {"name": "Entity Name", "type": "PERSON|PLACE|ORG|CONCEPT|EVENT", "confidence": 0.95}
  ],
  "relationships": [
    {"source": "Entity A", "target": "Entity B", "type": "WORKS_WITH", "confidence": 0.88}
  ]
}

Text: {text}
"""
```

### 2.3 Neo4j Graph Database

Stores entities as nodes and relationships as edges, enabling complex graph traversal queries.

**Node Structure:**
- `Entity` nodes: Core objects with properties (name, type, first_seen, last_seen)
- `Message` nodes: Original conversation segments
- `Session` nodes: Conversation groupings

**Relationship Types:**
- `MENTIONED_IN`: Entity → Message
- `RELATED_TO`: Entity → Entity (typed relationships)
- `PART_OF`: Message → Session
- `FOLLOWS`: Message → Message (temporal ordering)

### 2.4 Qdrant Vector Database

Provides semantic similarity search using embeddings generated by `embeddingGemma`.

**Collection Structure:**
- Collection name: `mollygraph_embeddings`
- Vector size: 768 dimensions (embeddingGemma output)
- Distance metric: Cosine similarity
- Payload includes: message_id, session_id, timestamp, entities mentioned

### 2.6 Ollama Integration Layer

Manages local model inference for entity extraction and embedding generation.

**Models Used:**
- **Gemma3:4b**: Primary entity/relationship extraction (4B parameters, fast)
- **embeddingGemma**: Text embeddings (768-dim, optimized for semantic search)

```python
# Ollama client wrapper
import aiohttp

class OllamaClient:
    def __init__(self, base_url="http://localhost:11434"):
        self.base_url = base_url
    
    async def extract_entities(self, text: str) -> dict:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                f"{self.base_url}/api/generate",
                json={
                    "model": "gemma3:4b",
                    "prompt": EXTRACTION_PROMPT.format(text=text),
                    "stream": False,
                    "format": "json"
                }
            ) as resp:
                result = await resp.json()
                return json.loads(result["response"])
    
    async def embed(self, text: str) -> list[float]:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                f"{self.base_url}/api/embeddings",
                json={"model": "embeddingGemma", "prompt": text}
            ) as resp:
                result = await resp.json()
                return result["embedding"]
```

**Step 3: Neo4j Graph Storage**

```python
async def store_in_neo4j(request, extraction):
    """
    Creates/merges nodes and relationships in the graph.
    Uses MERGE to avoid duplicates.
    """
    async with neo4j_driver.session() as session:
        # Create message node
        await session.run("""
            CREATE (m:Message {
                id: $msg_id,
                content: $content,
                timestamp: datetime($timestamp),
                author: $author
            })
            WITH m
            MATCH (s:Session {id: $session_id})
            CREATE (m)-[:PART_OF]->(s)
        """, {
            "msg_id": request.message_id,
            "content": request.content,
            "timestamp": request.timestamp,
            "author": request.author,
            "session_id": request.session_id
        })
        
        # Create/merge entities and link to message
        for entity in extraction["entities"]:
            if entity["confidence"] < 0.7:  # Filter threshold
                continue
                
            await session.run("""
                MERGE (e:Entity {name: $name, type: $type})
                ON CREATE SET e.first_seen = datetime($timestamp)
                ON MATCH SET e.last_seen = datetime($timestamp)
                WITH e
                MATCH (m:Message {id: $msg_id})
                CREATE (e)-[:MENTIONED_IN {
                    confidence: $confidence,
                    timestamp: datetime($timestamp)
                }]->(m)
            """, {
                "name": entity["name"],
                "type": entity["type"],
                "confidence": entity["confidence"],
                "timestamp": request.timestamp,
                "msg_id": request.message_id
            })
        
        # Create relationships between entities
        for rel in extraction["relationships"]:
            if rel["confidence"] < 0.7:
                continue
                
            await session.run("""
                MATCH (e1:Entity {name: $source})
                MATCH (e2:Entity {name: $target})
                MERGE (e1)-[r:RELATED_TO {type: $type}]->(e2)
                ON CREATE SET r.first_seen = datetime($timestamp),
                              r.confidence = $confidence
                ON MATCH SET r.last_seen = datetime($timestamp),
                             r.confidence = CASE 
                                 WHEN $confidence > r.confidence THEN $confidence 
                                 ELSE r.confidence 
                             END
            """, {
                "source": rel["source"],
                "target": rel["target"],
                "type": rel["type"],
                "confidence": rel["confidence"],
                "timestamp": request.timestamp
            })
```

    Stores vector representation for semantic similarity search.
    Payload includes searchable metadata.

### 3.3 Context Retrieval Flow

When answering a user query, the system retrieves relevant context:

```python
@app.post("/get_context")
async def get_context(request: ContextRequest):
    """
    Retrieves relevant context for a user query.
    Combines semantic search + graph traversal.
    """
    query = request.query
    max_results = request.max_results or 10
    
    # Parallel retrieval strategies
    results = await asyncio.gather(
        semantic_search(query, max_results),
        entity_graph_search(query, max_results),
        recent_session_context(request.session_id, limit=5)
    )
    
    semantic_results, graph_results, recent_results = results
    
    # Merge and deduplicate by message_id
    all_messages = {}
    for msg_list in [semantic_results, graph_results, recent_results]:
        for msg in msg_list:
            msg_id = msg["id"]
            if msg_id not in all_messages:
                all_messages[msg_id] = msg
                all_messages[msg_id]["sources"] = []
            all_messages[msg_id]["sources"].append(msg.get("source", "unknown"))
    
    # Sort by relevance score (if available) then timestamp
    sorted_messages = sorted(
        all_messages.values(),
        key=lambda x: (x.get("score", 0), x.get("timestamp", "")),
        reverse=True
    )
    
    return {
        "query": query,
        "messages": sorted_messages[:max_results],
        "entities_found": list(set(
            e for m in sorted_messages for e in m.get("entities", [])
        ))
    }

async def semantic_search(query: str, limit: int) -> list:
    """Vector similarity search via Qdrant."""
    query_embedding = await ollama.embed(query)
    
    search_result = await qdrant_client.search(
        collection_name="mollygraph_embeddings",
        query_vector=query_embedding,
        limit=limit,
        with_payload=True
    )
    
    return [{
        "id": r.id,
        "text": r.payload["text"],
        "score": r.score,
        "session_id": r.payload["session_id"],
        "timestamp": r.payload["timestamp"],
        "source": "semantic"
    } for r in search_result]

async def entity_graph_search(query: str, limit: int) -> list:
    """Extract entities from query, then traverse graph."""
    # Extract entities from the query itself
    extraction = await ollama.extract_entities(query)
    entity_names = [e["name"] for e in extraction["entities"]]
    
    if not entity_names:
        return []
    
    # Find messages mentioning these entities
    async with neo4j_driver.session() as session:
        result = await session.run("""
            MATCH (e:Entity)
            WHERE e.name IN $entity_names
            MATCH (e)-[:MENTIONED_IN]->(m:Message)
            RETURN m.id as id, m.content as text, m.timestamp as timestamp,
                   collect(e.name) as entities
            ORDER BY m.timestamp DESC
            LIMIT $limit
        """, {"entity_names": entity_names, "limit": limit})
        
        records = await result.data()
        return [{
            "id": r["id"],
            "text": r["text"],
            "timestamp": r["timestamp"],
            "entities": r["entities"],
            "source": "graph"
        } for r in records]
```

## 4. Storage Details

### 4.1 Neo4j Graph Schema

The graph structure is designed for efficient traversal and relationship analysis.

**Node Labels & Properties:**

| Label | Key Properties | Purpose |
|-------|----------------|---------|
| `Entity` | `name`, `type`, `first_seen`, `last_seen`, `mention_count` | People, places, organizations, concepts |
| `Message` | `id`, `content`, `timestamp`, `author`, `word_count` | Individual conversation messages |
| `Session` | `id`, `created_at`, `title`, `message_count` | Conversation groupings |
| `Concept` | `name`, `category`, `description` | Abstract ideas and topics |
| `Event` | `name`, `date`, `location`, `participants` | Time-bound occurrences |

**Relationship Types & Properties:**

| Relationship | Direction | Properties | Purpose |
|--------------|-----------|------------|---------|
| `MENTIONED_IN` | Entity → Message | `confidence`, `timestamp` | Links entities to their source messages |
| `RELATED_TO` | Entity → Entity | `type`, `confidence`, `first_seen`, `last_seen` | Typed relationships between entities |
| `PART_OF` | Message → Session | `order` (sequence number) | Groups messages into sessions |
| `FOLLOWS` | Message → Message | `time_delta` | Temporal ordering within a session |
| `PARTICIPATED_IN` | Entity → Event | `role` | Event participation tracking |
| `SUBCLASS_OF` | Concept → Concept | `confidence` | Hierarchical concept relationships |

**Cypher Schema Definition:**

```cypher
// Create constraints for data integrity
CREATE CONSTRAINT entity_name_type IF NOT EXISTS
FOR (e:Entity) REQUIRE (e.name, e.type) IS UNIQUE;

CREATE CONSTRAINT message_id IF NOT EXISTS
FOR (m:Message) REQUIRE m.id IS UNIQUE;

CREATE CONSTRAINT session_id IF NOT EXISTS
FOR (s:Session) REQUIRE s.id IS UNIQUE;

// Create indexes for performance
CREATE INDEX entity_type_idx IF NOT EXISTS FOR (e:Entity) ON (e.type);
CREATE INDEX entity_last_seen_idx IF NOT EXISTS FOR (e:Entity) ON (e.last_seen);
CREATE INDEX message_timestamp_idx IF NOT EXISTS FOR (m:Message) ON (m.timestamp);
CREATE INDEX rel_type_idx IF NOT EXISTS FOR ()-[r:RELATED_TO]-() ON (r.type);
```

**Example Graph Queries:**

```cypher
// Find all messages mentioning a specific entity
MATCH (e:Entity {name: "Brian"})-[:MENTIONED_IN]->(m:Message)
RETURN m.content, m.timestamp
ORDER BY m.timestamp DESC
LIMIT 10;

// Find relationship path between two entities
MATCH path = shortestPath(
    (e1:Entity {name: "Brian"})-[:RELATED_TO*]-(e2:Entity {name: "OpenClaw"})
)
RETURN path;

// Find most connected entities (hubs)
MATCH (e:Entity)-[:RELATED_TO]-(other)
WITH e, count(other) as connections
ORDER BY connections DESC
LIMIT 10
RETURN e.name, e.type, connections;

// Temporal analysis: Entity mentions over time
MATCH (e:Entity)-[m:MENTIONED_IN]->(:Message)
WHERE m.timestamp > datetime() - duration('P7D')
RETURN e.name, count(m) as mentions
ORDER BY mentions DESC;
```

## 5. Query Patterns

MollyGraph supports multiple query patterns for retrieving context, each optimized for different use cases.

### 5.1 Semantic Search Pattern

Retrieves messages based on meaning similarity rather than keyword matching.

```python
async def semantic_context_retrieval(query: str, limit: int = 10) -> list[dict]:
    """
    Primary retrieval method: Uses vector similarity to find 
    conceptually related messages even without keyword overlap.
    """
    # Generate query embedding
    query_vector = await ollama.embed(query)
    
    # Search Qdrant with optional filters
    results = await qdrant_client.search(
        collection_name="mollygraph_embeddings",
        query_vector=query_vector,
        limit=limit,
        query_filter=models.Filter(
            must=[
                # Only retrieve user messages (not assistant responses)
                models.FieldCondition(
                    key="author",
                    match=models.MatchValue(value="user")
                )
            ]
        ),
        with_payload=True,
        score_threshold=0.7  # Minimum similarity score
    )
    
    return [
        {
            "message_id": r.id,
            "text": r.payload["text"],
            "similarity_score": r.score,
            "timestamp": r.payload["timestamp"],
            "session_id": r.payload["session_id"]
        }
        for r in results
    ]
```

**When to use:** General context retrieval, vague queries, finding related concepts.

### 5.2 Entity-Centric Graph Traversal

Finds messages by following entity relationships through the graph.

```python
async def entity_based_retrieval(query: str, depth: int = 2) -> list[dict]:
    """
    Extract entities from query, then traverse graph to find:
    1. Direct mentions of extracted entities
    2. Related entities within N hops
    3. Messages mentioning related entities
    """
    # Step 1: Extract entities from the query
    extraction = await ollama.extract_entities(query)
    query_entities = [e["name"] for e in extraction["entities"] if e["confidence"] > 0.7]
    
    if not query_entities:
        return []
    
    async with neo4j_driver.session() as session:
        # Step 2: Find related entities and messages
        result = await session.run("""
            // Match query entities
            MATCH (query_entity:Entity)
            WHERE query_entity.name IN $query_entities
            
            // Find related entities (1-2 hops away)
            OPTIONAL MATCH path = (query_entity)-[rel:RELATED_TO*1..$depth]-(related:Entity)
            
            // Get all messages mentioning either query or related entities
            WITH query_entity, related, relationships(path) as rels
            MATCH (related)-[m:MENTIONED_IN]->(msg:Message)
            
            // Calculate relevance score based on:
            // - Direct mention (higher score)
            // - Relationship path length (shorter = higher score)
            // - Confidence scores
            RETURN 
                msg.id as message_id,
                msg.content as text,
                msg.timestamp as timestamp,
                collect(DISTINCT related.name) as matched_entities,
                CASE 
                    WHEN related.name IN $query_entities THEN 1.0
                    ELSE 0.8 / length(rels)
                END as relevance_score
            ORDER BY relevance_score DESC, msg.timestamp DESC
            LIMIT 20
        """, {"query_entities": query_entities, "depth": depth})
        
        records = await result.data()
        return records
```

**When to use:** Named entity queries, relationship questions ("Who works with Brian?"), structured lookups.

### 5.3 Temporal Context Retrieval

Retrieves messages within a time window, optionally combined with other filters.

```python
async def temporal_retrieval(
    start_time: datetime,
    end_time: datetime,
    session_id: str = None
) -> list[dict]:
    """
    Retrieves messages from a specific time period.
    Useful for "What did we discuss yesterday?" type queries.
    """
    async with neo4j_driver.session() as session:
        query = """
            MATCH (m:Message)
            WHERE m.timestamp >= $start_time 
              AND m.timestamp <= $end_time
        """
        
        params = {
            "start_time": start_time.isoformat(),
            "end_time": end_time.isoformat()
        }
        
        if session_id:
            query += " AND m.session_id = $session_id"
            params["session_id"] = session_id
        
        query += """
            OPTIONAL MATCH (e:Entity)-[:MENTIONED_IN]->(m)
            RETURN m.id as message_id,
                   m.content as text,
                   m.timestamp as timestamp,
                   m.author as author,
                   collect(e.name) as entities
            ORDER BY m.timestamp ASC
        """
        
        result = await session.run(query, params)
        return await result.data()

# Usage example: "What did we discuss yesterday?"
yesterday = datetime.now() - timedelta(days=1)
context = await temporal_retrieval(
    start_time=yesterday.replace(hour=0, minute=0),
    end_time=yesterday.replace(hour=23, minute=59)
)
```

**When to use:** Time-based queries, session reconstruction, chronological review.

### 5.4 Hybrid Retrieval (Combined Approach)

The most effective pattern combines multiple retrieval strategies and reranks results.

```python
async def hybrid_context_retrieval(
    query: str,
    session_id: str = None,
    max_results: int = 15
) -> dict:
    """
    Combines semantic search, entity graph traversal, and temporal recency
    to provide comprehensive context for answering queries.
    """
    # Execute all retrieval strategies in parallel
    results = await asyncio.gather(
        # Strategy 1: Semantic similarity
        semantic_search(query, limit=20),
        
        # Strategy 2: Entity graph traversal  
        entity_graph_search(query, depth=2, limit=15),
        
        # Strategy 3: Recent session context
        recent_session_context(session_id, limit=10) if session_id else [],
        
        # Strategy 4: Extract entities from query for entity list
        ollama.extract_entities(query)
    )
    
    semantic_results, graph_results, recent_results, extraction = results
    query_entities = [e["name"] for e in extraction.get("entities", [])]
    
    # Merge and score results
    scored_messages = {}
    
    # Score semantic results (normalized 0-1)
    for msg in semantic_results:
        msg_id = msg["id"]
        scored_messages[msg_id] = {
            **msg,
            "semantic_score": msg.get("score", 0),
            "graph_score": 0,
            "recency_score": 0,
            "entity_matches": []
        }
    
    # Score graph results
    for msg in graph_results:
        msg_id = msg["id"]
        if msg_id not in scored_messages:
            scored_messages[msg_id] = {
                **msg,
                "semantic_score": 0,
                "graph_score": 0,
                "recency_score": 0,
                "entity_matches": []
            }
        scored_messages[msg_id]["graph_score"] = msg.get("relevance_score", 0.5)
        scored_messages[msg_id]["entity_matches"] = msg.get("entities", [])
    
    # Calculate recency score (exponential decay)
    now = datetime.now()
    for msg_id, msg in scored_messages.items():
        msg_time = datetime.fromisoformat(msg["timestamp"].replace('Z', '+00:00'))
        days_old = (now - msg_time).days
        msg["recency_score"] = math.exp(-days_old / 30)  # 30-day half-life
    
    # Combined scoring with weights
    for msg in scored_messages.values():
        msg["combined_score"] = (
            0.4 * msg["semantic_score"] +
            0.35 * msg["graph_score"] +
            0.25 * msg["recency_score"]
        )
    
    # Sort and return top results
    sorted_messages = sorted(
        scored_messages.values(),
        key=lambda x: x["combined_score"],
        reverse=True
    )[:max_results]
    
    return {
        "query": query,
        "query_entities": query_entities,
        "messages": sorted_messages,
        "sources_used": ["semantic", "graph", "recent"] if session_id else ["semantic", "graph"]
    }
```

async def consolidate_session(session_id: str, age_days: int = 30):
    """
    Summarize old messages and replace with condensed version.
    Preserves entity links but reduces storage.
    """
    # Find old messages
    old_messages = await neo4j_session.run("""
        MATCH (m:Message)-[:PART_OF]->(s:Session {id: $session_id})
        WHERE m.timestamp < datetime() - duration('P' + $age_days + 'D')
        RETURN m.id as id, m.content as content, m.timestamp as timestamp
        ORDER BY m.timestamp
    """, {"session_id": session_id, "age_days": age_days})
    
    # Batch into chunks and summarize
    chunks = group_into_batches(old_messages, batch_size=10)
    
    for chunk in chunks:
        summary = await llm.summarize(
            messages=chunk,
            instruction="Create a concise summary preserving key facts, decisions, and entities"
        )
        
        # Create summary node
        await neo4j_session.run("""
            CREATE (sum:Summary {
                id: $summary_id,
                content: $summary,
                start_time: $start,
                end_time: $end,
                original_count: $count
            })
            WITH sum
            MATCH (s:Session {id: $session_id})
            CREATE (sum)-[:SUMMARIZES]->(s)
            
            // Transfer entity relationships
            WITH sum
            MATCH (e:Entity)-[:MENTIONED_IN]->(m:Message)
            WHERE m.id IN $message_ids
            CREATE (e)-[:MENTIONED_IN {via_summary: true}]->(sum)
        """, {...})
        
        // Remove old vectors (keep graph for structure)
        await qdrant_client.delete(
            collection_name="mollygraph_embeddings",
            points_selector=chunk.message_ids
        )

async def prune_irrelevant_memories(user_id: str):
    """
